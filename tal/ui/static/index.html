模型接入

选择本地模型。三种接入方式：内置模拟（离线演示）、OpenAI 兼容端点（Ollama / LM Studio / vLLM / llama.cpp server）、本地 HF 权重目录。定向消融需要本地权重；远程端点只能用于对话与能力测试。

新增模型

HF 目录需含 config.json 与权重文件；也可以填单个 .gguf 文件（走 ditch 引擎）。OpenAI 兼容端点若同时填写该路径，对话走端点、消融用本地权重。

ditch 可以直接消融 GGUF；TAL 的基座/KL 评测仍需要原始 HF 权重，因此 GGUF 输入必须同时给出 HF 快照目录。Heretic 只用上面的路径，可留空此项。

HF 目录需含 config.json 与权重文件。4bit 量化需要 bitsandbytes。敏感 API Key 只保存在本机 ui-data/config.json，不会回传给页面。

请求库

三类库：target 是希望模型不再照做的请求（用于定向拒答）；preserve 是必须保持正常的日常请求（用于约束 KL 漂移）；capability 是带标准答案的选择题（用于能力测试）。target / preserve 一行一条；capability 为 JSONL。

已保存的库

新建请求库

每行一条；空行与 # 开头的行会被忽略。至少 3 条，建议 ≥ 12 条以便切分。

对话探测

直接问模型，查看回答与关键词判定。这里的“拒绝”只是关键词规则，不等于实验里的统计结论；它用于快速确认模型是否真的在回答。

批量探测请求库

用当前“模型”下拉框选中的模型，逐条发送一个请求库，标出哪些答复被判为拒答。适合在消融前确认“这批请求确实被拒绝”。
